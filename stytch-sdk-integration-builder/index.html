Stytch · SDK Integration Builder

Driving SDK Adoption

Prebuilt UI was supposed to be the fastest path to auth — no components to build. Adoption said otherwise.

The Problem

Fast Auth, Slow Evaluation

The Stytch SDK's whole pitch was fast auth — nothing to build. But evaluating Stytch wasn't fast at all: customers had no way to know if the SDK actually fit their product without integrating it first.

Context

Our team's first read was a capability gap, so we focused on closing API gaps first. But even after closing them, customers still weren't adopting the SDK like we expected.

Who This Is For

Two Audiences, One Tool

The Evaluator

A developer or team deciding whether Stytch fits their product, before writing any integration code.

For Example

A customer sizing up Stytch for their own app's auth

The Solutions Engineer

Stytch's own team, who used to build one-off demos by hand to answer exactly the question the Evaluator is asking.

For Example

An SE on a prospect call

The Ask

Can a Customer See Their Own Product Here?

Customers kept asking the same thing: what would this actually look like inside their product? The closest Stytch had were example apps.

Reference Apps

The Solution

The Answer Wasn't Another Demo — It Was a Tool

Reference apps were still just examples — not something built around a customer's own product. What customers actually needed was a way to interact with the SDK directly, without integrating anything first.

The Idea

The SDK Integration Builder: an interactive playground, live before any code is written.

The Customer Evaluation Journey

Stytch's full product catalog, right there to click through — customers don't need to dig through docs or the marketing site to understand how something works.

It wasn't easy to see how our SDK's configuration mapped to UI elements. We started by cleaning up the actual API properties (i.e., consolidate styles, simplify the overall config), and from there created an easy way to change properties with a live preview visible.

Instead of just a preview of what your customizations would look like, a full working SDK instance. Customers click through the real sign-up/login flow so they can see each phase of the flow.

View Code turns the config into a real integration the moment evaluation ends with production ready code.

Impact

What This Actually Fixed

  • Fast, easy preview

    Replaced the SE-built custom demo as the default way a customer evaluates Stytch.

  • Reduced time to value

    View Code turns the end of evaluation directly into a working integration.

  • Better decision-making

    Customers validate product fit, brand fit, and real UX flows themselves.

Try it yourself — toggle products, restyle it, view the code

Product and styling changes are fully live — email/SMS delivery isn't connected in this demo, so a real message won't send.
